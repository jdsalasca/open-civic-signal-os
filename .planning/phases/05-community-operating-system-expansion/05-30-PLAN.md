# Phase 5.30 Plan - Privacy Center and Sensitive-Data Access Logs

## Objective

Implement `story:OCS-P1-050` so users and community coordinators can control visibility and open-data publication settings through backend-owned privacy rules while every sensitive read leaves an auditable access trail.

## Scope

- extend backend privacy preferences beyond profile-only visibility to include activity visibility and open-data publication controls
- add a community-scoped privacy policy model for open-data publication settings owned by coordinators
- create access-log events for sensitive data reads and expose reviewable privacy-log APIs
- surface a privacy center in the existing settings workflow and add coordinator-facing community privacy controls
- update OpenAPI, ADR, changelog, and GSD state so the next canonical story remains `OCS-P1-051`

## Acceptance Criteria

- users can control visibility for profile and participation activity from one privacy center
- coordinators can define one active community open-data publication policy without frontend-owned governance logic
- sensitive data reads are logged with actor, scope, target, timestamp, and policy context
- access logs are reviewable by the affected user and by authorized community coordinators where relevant
- backend, contract, frontend, docs, and tests are updated in one change set

## Validation

- `npm run agent:context:check`
- `npm run backlog:current:check`
- `npm run agent:adr:check`
- targeted backend integration tests for privacy preferences and access-log review
- `mvn -q test` in `apps/api-java`
- `npm run docker:dev:doctor`
- `npm run docker:dev:up`
- frontend build and privacy-center evidence through the Docker runtime
