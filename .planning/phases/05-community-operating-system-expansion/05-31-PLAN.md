# Phase 5.31 Plan - Civic Onboarding and Help Center

## Objective

Implement `story:OCS-P1-051` so citizens, moderators, and representatives can discover the product through backend-owned onboarding state, searchable bilingual help content, and contextual guidance that can be dismissed and revisited without losing community context.

## Scope

- add backend onboarding state persisted per user with explicit role-aware steps and dismiss/revisit support
- add backend-owned help-center article and module endpoints with bilingual content and search/filter semantics
- expose one dedicated help-center route in the frontend
- surface contextual help modules in the highest-value workflows:
  - dashboard
  - report
  - communities
  - proposals
  - governance
  - projects
- keep role selection, guide eligibility, and onboarding completion logic backend-owned
- update OpenAPI, ADR, changelog, and GSD state so the next canonical story becomes `OCS-P1-052`

## Acceptance Criteria

- onboarding exists for citizens, moderators, and representatives with distinct step copy and route targets
- help content is searchable and bilingual from one help-center route
- users can dismiss and later revisit contextual guides without resetting unrelated app state
- contextual help can be opened from key workflows without navigating users away from their active community context
- backend, contract, frontend, docs, and tests are updated in one change set

## Validation

- `npm run agent:context:check`
- `npm run backlog:current:check`
- `npm run agent:adr:check`
- targeted backend integration tests for onboarding state and help-center responses
- `mvn -q test` in `apps/api-java`
- `npm run docker:dev:up`
- frontend build and help-center evidence through the Docker runtime
