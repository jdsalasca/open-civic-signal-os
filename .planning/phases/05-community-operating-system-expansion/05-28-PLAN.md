# Phase 5.28 Plan - Verifiable Community Voting

## Objective

Implement `story:OCS-P1-042` so structured proposals can collect auditable, backend-owned community votes before they are promoted into formal decisions.

## Scope

- extend proposal domain and migration with configurable vote mode, visibility, eligibility, and voting window
- add backend vote casting/read APIs with duplicate protection, verification checks, and anti-abuse audit counters
- surface proposal voting inside `/communities/proposals` with clear eligibility messaging and tally visibility rules
- update OpenAPI, ADR, changelog, and GSD sequencing so the next canonical story becomes `OCS-P1-049`

## Acceptance Criteria

- one-person-one-vote is enforced deterministically per proposal
- result visibility obeys proposal configuration (`COMMUNITY` or `AFTER_VOTE`)
- verified-only votes are blocked and auditable when eligibility requires it
- proposal detail makes vote status, tally visibility, and current-user state explicit
- contract, docs, and tests are updated in the same change set

## Validation

- `npm run agent:context:check`
- `npm run backlog:current:check`
- `npm run agent:adr:check`
- `mvn -q -Dtest=CommunityProposalVotingIT,CommunityProposalIT test`
- `mvn -q test` in `apps/api-java`
- Playwright wrapper evidence if Docker/browser path is available
