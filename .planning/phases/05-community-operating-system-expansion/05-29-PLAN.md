# Phase 5.29 Plan - Moderation Queue and Sanction Engine

## Objective

Implement `story:OCS-P1-049` so community participation surfaces can be reported, reviewed, and sanctioned through one auditable moderation workflow instead of disconnected hidden actions.

## Scope

- add a backend-owned moderation report and sanction ladder model with explicit reason codes, statuses, and actor metadata
- expose community-scoped moderation queue and action endpoints that preserve content traceability across signals, proposal deliberation, and community threads
- enforce policy checks and active-sanction guardrails through existing community access services
- replace the legacy signal-only moderation view with a moderator queue that shows report reasons, target context, and enforcement outcomes
- update OpenAPI, ADR, changelog, and GSD state/history so the next canonical story becomes `OCS-P1-050`

## Acceptance Criteria

- community members can report supported content with an explicit reason and freeform evidence note
- moderators see an auditable queue with target type, report status, reporter count, sanction state, and preserved source context
- sanctions are proportional, reversible where appropriate, and always carry a policy reason
- active sanctions block protected community actions without deleting the underlying traceability record
- contract, docs, and tests are updated in the same change set
