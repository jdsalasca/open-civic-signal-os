# Phase 5.26 Plan - Community Decision Ledger

## Objective

Implement `story:OCS-P1-047` so communities can trace proposals into formal decisions, see the approval basis, and connect decisions to execution ownership.

## Scope

- add a backend-owned community decision-ledger domain and persistence model
- expose list/detail/create endpoints under the community collaboration API
- link decisions to proposal, governance document, and project board where applicable
- expose approval-basis metadata and execution owner information
- add a dedicated frontend route for browsing and creating decision ledger entries
- update OpenAPI, ADR, changelog, and GSD state/backlog references

## Acceptance Criteria

- each decision record belongs to one community and links to a source proposal or governance record
- approval basis is explicit and visible even before full voting infrastructure lands
- linked execution board and responsible owner are visible where applicable
- coordinator-facing creation flow exists and member-facing browsing stays legible on mobile
- contract, docs, and tests are updated in the same change set

## Validation

- `npm run agent:context:check`
- `npm run backlog:current:check`
- `npm run agent:adr:check`
- targeted backend integration test for decision ledger
- `mvn -q test` in `apps/api-java` if environment allows
- Playwright wrapper evidence if frontend changes and Docker/browser path is available
