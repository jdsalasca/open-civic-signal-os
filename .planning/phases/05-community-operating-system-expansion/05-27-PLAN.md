# Phase 5.27 Plan - Public Trust Metrics Dashboard

## Objective

Implement `story:OCS-P1-048` so communities can see outcome proof, participation coverage, execution progress, and freshness from one backend-owned trust dashboard.

## Scope

- add a backend-owned trust-metrics aggregation service with deterministic period windows
- expose a community trust metrics endpoint with cards, breakdowns, freshness, and low-data semantics
- add a frontend `/communities/trust` route with period filtering and drill-down cards
- update OpenAPI, ADR, changelog, and GSD backlog/state references

## Acceptance Criteria

- freshness and time period are visible in every trust metrics payload and route state
- metric cards explain what they mean in plain language and expose backend-owned formulas
- low-data communities receive understandable fallback messaging instead of silent empty charts
- the trust route remains legible in both simple and advanced modes
- contract, docs, and tests are updated in the same change set

## Validation

- `npm run agent:context:check`
- `npm run backlog:current:check`
- `npm run agent:adr:check`
- targeted backend integration test for trust metrics
- `mvn -q test` in `apps/api-java` if environment allows
- Playwright wrapper evidence if Docker/browser path is available
